Sincronización con Google Drive

Esta guía describe el proceso completo de configuración de la autenticación OAuth 2.0 para sincronizar las sesiones de captura con Google Drive de forma automática.

Nota: Esta configuración se realiza una sola vez desde la PC. Una vez completada, la Raspberry Pi sincroniza de forma autónoma al seleccionar el modo de sincronización mediante el interruptor.

Requisitos previos

  • Cuenta de Google con Google Drive activo (telematica.vehicular.utm@gmail.com)
  • Acceso a Google Cloud Console
  • Python 3 instalado en la PC
  • Conexión SSH a la Raspberry Pi

Paso 1 — Crear proyecto en Google Cloud Console

  1. Acceder a console.cloud.google.com
  2. Crear un nuevo proyecto: proyecto-gnss
  3. En el menú lateral ir a APIs & Services → Library
  4. Buscar y habilitar la API: Google Drive API

Paso 2 — Completar la información de Branding

En el menú lateral de Google Auth Platform ir a Branding y completar los campos obligatorios:

  • App name: rpi-gnss
  • User support email: correo del proyecto
  • Application home page: URL del repositorio en GitHub
  • Application privacy policy link: URL del archivo PRIVACY.md en GitHub
  • Developer contact information: correo del desarrollador

Hacer clic en Save para guardar los cambios.

Nota sobre el archivo PRIVACY.md: debe existir en la raíz del repositorio antes de guardar la configuración. La URL tiene la forma https://github.com/USUARIO/REPOSITORIO/blob/main/PRIVACY.md. El segmento blob/main no es una carpeta — es la forma en que GitHub construye la URL para visualizar archivos; el archivo debe estar en la raíz del repositorio.

Paso 3 — Publicar la aplicación en producción

Este paso es fundamental para garantizar que el token de autenticación no expire. Las aplicaciones en modo Testing tienen sus tokens revocados automáticamente después de 7 días, lo que requeriría regenerar el token semanalmente.

  1. En el menú lateral de Google Auth Platform ir a Audience
  2. La sección Publishing status mostrará el estado Testing con el botón Publish app
  3. Si el botón aparece deshabilitado con el mensaje "complete your configuration on the Branding page", es necesario completar primero el Paso 2
  4. Una vez habilitado, hacer clic en Publish app y confirmar
  5. El estado debe cambiar a In production

Beneficios de publicar en producción:

  • El token de autenticación no expira por política de Google
  • El sistema sincroniza de forma completamente autónoma sin intervención manual
  • No es necesario regenerar el token periódicamente
  • El access token de corta duración (60 minutos) se renueva de forma automática usando el refresh token almacenado en token.json

Sin publicar la aplicación, el token expira cada 7 días y la sincronización falla con el error invalid_grant: Token has been expired or revoked.

Paso 4 — Crear credenciales OAuth

  1. Ir a APIs & Services → Credentials
  2. Hacer clic en Create Credentials → OAuth client ID
  3. Tipo de aplicación: Desktop app
  4. Nombre: rpi-gnss-client
  5. Descargar el archivo JSON de credenciales
  6. Renombrar el archivo a client_secret.json

Paso 5 — Preparar el entorno en la PC

Crear un entorno virtual temporal e instalar las dependencias necesarias:

Linux / macOS:

python3 -m venv /tmp/oauth_env
source /tmp/oauth_env/bin/activate
pip install google-auth-oauthlib google-api-python-client

Windows:

python -m venv %TEMP%\oauth_env
%TEMP%\oauth_env\Scripts\activate
pip install google-auth-oauthlib google-api-python-client

Paso 6 — Generar el token de autenticación

Colocar client_secret.json y autorizar.py en el mismo directorio y ejecutar:

python3 autorizar.py

Se abrirá el navegador solicitando autorización. Al aparecer la advertencia "Google hasn't verified this app":

  1. Hacer clic en Advanced
  2. Hacer clic en Go to rpi-gnss (unsafe)
  3. Seleccionar la cuenta del proyecto y autorizar el acceso a Google Drive

El script generará el archivo token.json en el directorio actual.

Nota sobre la advertencia de seguridad: La advertencia "Google hasn't verified this app" es normal para aplicaciones propias que no han pasado por el proceso de verificación formal de Google. Al ser el desarrollador de la aplicación, es seguro continuar.

Paso 7 — Copiar el token a la Raspberry Pi

scp token.json adq@<IP_RASPBERRY>:/home/adq/proyecto-gnss/token.json

Sustituir <IP_RASPBERRY> por la dirección IP de la Raspberry Pi en la red local.

Paso 8 — Verificar la sincronización

Conectarse por SSH a la Raspberry Pi y ejecutar:

cd /home/adq/proyecto-gnss
source env_librerias_gnss/bin/activate
python3 sincronizacion.py

Una sincronización exitosa produce una salida similar a:

[SYNC] INFO: Sesiones pendientes: 2
[SYNC] INFO: Conexión a internet disponible.
[SYNC] INFO: Conectado a Google Drive
[SYNC] INFO: Sincronizando sesión 20260926_154149...
[SYNC] INFO:   Carpeta del día creada: 20260926
[SYNC] INFO:   Subiendo imu_20260926_154149.csv (intento 1/3)...
[SYNC] INFO:   imu_20260926_154149.csv verificado.
[SYNC] INFO:   ✓ imu_20260926_154149.csv eliminado localmente
[SYNC] INFO: Sesión 20260926_154149 sincronizada correctamente.
[SYNC] INFO: Sincronización completada: 2/2 sesiones.

Resultado: 2/2 sesiones sincronizadas.

Comportamiento del sistema

  • Organización en Drive: los archivos se organizan en carpetas por día con formato YYYYMMDD dentro de la carpeta principal del proyecto
  • Verificación de integridad: cada archivo se verifica mediante MD5 antes de eliminarse localmente
  • Reintentos automáticos: en caso de error de red, el sistema reintenta la subida hasta 3 veces con 5 segundos de espera entre intentos
  • Sesión válida: una sesión debe contener al menos el archivo IMU para ser sincronizada; GNSS y barométrico son opcionales
  • Eliminación local: los archivos se eliminan de la Raspberry Pi únicamente después de confirmar la subida exitosa mediante MD5
  • Renovación automática del token: el access token se renueva de forma automática usando el refresh token en token.json; no requiere intervención manual

Solución de problemas

Error: invalid_grant: Token has been expired or revoked

La causa más común es que la aplicación se encontraba en modo Testing — Google revoca automáticamente los tokens de aplicaciones en modo prueba después de 7 días.

Solución: verificar que la aplicación esté publicada en producción (Paso 3), regenerar el token (Pasos 5 y 6) y copiarlo a la Raspberry Pi (Paso 7).

Error: invalid_grant: Bad Request

Variante del error anterior con la misma causa y solución.

Sin conexión WiFi

El sistema espera hasta 60 segundos a que haya conexión a internet antes de intentar sincronizar. Si no hay conexión disponible, el proceso termina sin subir archivos. Los archivos permanecen en la Raspberry Pi y serán sincronizados en la siguiente sesión.
