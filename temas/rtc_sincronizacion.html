RTC y sincronización horaria

La Raspberry Pi 5 incluye un reloj de tiempo real (RTC) respaldado por batería. Esta guía describe su funcionamiento, la verificación de persistencia y el mecanismo de recalibración automática en cada sincronización.

¿Qué es el RTC y por qué importa?

El RTC (Real-Time Clock) es un circuito integrado que mantiene la hora del sistema aunque el dispositivo esté apagado o sin conexión a internet. En la Raspberry Pi 5 el RTC está incorporado en el chip RP1 y se alimenta mediante una pequeña batería tipo RTC (conector J2).

En un sistema de adquisición vehicular la hora es un dato crítico: los archivos CSV de IMU, GNSS y barométrico se nombran con el timestamp de inicio de sesión (imu_YYYYMMDD_HHMMSS.csv) y cada muestra lleva una marca de tiempo. Si el RTC no está sincronizado, los datos de distintas sesiones no se pueden alinear correctamente durante el análisis.

Debian trixie

En Debian trixie (la distribución que corre en la Raspberry Pi 5) el servicio systemd-timesyncd gestiona el RTC de forma automática: cuando NTP está activo y la sincronización es exitosa, el RTC se actualiza sin intervención manual. La herramienta hwclock no está instalada y no es necesaria.

Batería del RTC — instalación

La Raspberry Pi 5 trae el conector J2 en la placa para conectar una batería RTC externa. Sin batería, el RTC pierde la hora cada vez que el dispositivo se apaga.

La batería compatible es de tipo ML2032 o equivalente recargable (la RPi 5 puede recargarla). Una batería no recargable estándar CR2032 también funciona, pero debe desactivarse el circuito de carga para evitar dañarla — consultar la documentación oficial de Raspberry Pi para este caso.

importante

El botón físico J2 de la Raspberry Pi 5 (botón de encendido de fábrica) y el conector J2 del RTC son componentes distintos en la placa. El conector del RTC es un header de 2 pines etiquetado BAT en algunas revisiones de la placa.

Cómo funciona la sincronización

El sistema opera en dos niveles:

Nivel 1 — Sincronización NTP al arrancar

Cada vez que la Raspberry Pi arranca con conexión a internet, systemd-timesyncd sincroniza automáticamente el reloj del sistema con los servidores NTP configurados. Una vez sincronizado, actualiza el RTC con la hora correcta. Este proceso ocurre en segundo plano sin intervención manual.

Nivel 2 — Recalibración explícita antes de sincronizar con Drive

El script sincronizacion.py llama a la función sincronizar_rtc() inmediatamente después de confirmar conexión a internet y antes de subir los archivos a Google Drive. Esta función:

  1. Activa NTP explícitamente con timedatectl set-ntp true
  2. Espera hasta 30 segundos a que systemd-timesyncd confirme sincronización
  3. Registra el resultado en el log del sistema

El resultado es que cada vez que el sistema sube datos a Drive, garantiza que el RTC esté actualizado para la siguiente sesión de captura.

# Fragmento de sincronizacion.py — función sincronizar_rtc()
def sincronizar_rtc():
    subprocess.run(['sudo', 'timedatectl', 'set-ntp', 'true'], ...)
    for _ in range(10):
        resultado = subprocess.run(
            ['timedatectl', 'show', '--property=NTPSynchronized', '--value'], ...
        )
        if resultado.stdout.strip() == 'yes':
            log.info('RTC sincronizado correctamente via NTP.')
            return
        time.sleep(3)
    log.warning('NTP no confirmó sincronización en 30 s.')

La función es tolerante a fallos: si NTP no responde o hay error, registra una advertencia en el log pero no interrumpe la subida de archivos.

Permiso sudo para timedatectl

La función sincronizar_rtc() ejecuta timedatectl set-ntp true con sudo. Para que esto funcione sin requerir contraseña (el script corre de forma desatendida), se configuró una regla en sudoers:

# Crear el archivo de regla
sudo visudo -f /etc/sudoers.d/gnss-rtc

Contenido del archivo:

adq ALL=(ALL) NOPASSWD: /bin/timedatectl set-ntp true

Verificar que la sintaxis es correcta antes de guardar:

sudo visudo -c -f /etc/sudoers.d/gnss-rtc
# Salida esperada: /etc/sudoers.d/gnss-rtc: parsed OK
seguridad

La regla NOPASSWD está restringida exactamente al comando /bin/timedatectl set-ntp true — no otorga privilegios adicionales al usuario adq.

Verificación de persistencia (H-03)

Para confirmar que la batería mantiene la hora correctamente cuando el dispositivo no tiene red, se realizó la siguiente prueba:

Procedimiento

  1. Deshabilitar NTP y establecer una hora falsa:
sudo timedatectl set-ntp false
sudo timedatectl set-time "2020-01-01 00:00:00"
sudo reboot
  1. Después del reinicio, verificar que el sistema arrancó con la hora del RTC (2020), no con la hora real:
timedatectl

Resultado observado — el RTC conservó la hora falsa, confirmando que la batería funciona:

       Local time: lun 2026-10-26 22:58:09 CST
     Universal time: mar 2026-10-27 04:58:09 UTC
           RTC time: mié 2020-01-01 06:02:02
          Time zone: America/Mexico_City (CST, -0600)
System clock synchronized: no
          NTP service: inactive
      RTC in local TZ: no
  1. Restaurar la sincronización NTP:
sudo timedatectl set-ntp true
  1. Verificar sincronización exitosa:
timedatectl
       Local time: lun 2026-10-26 23:00:15 CST
     Universal time: mar 2026-10-27 05:00:15 UTC
           RTC time: mar 2026-10-27 05:00:15
System clock synchronized: yes
          NTP service: active
      RTC in local TZ: no
verificado

H-03 completado — 2026-10-27. El RTC mantiene la hora sin conexión a red. Al restablecer NTP, el reloj del sistema y el RTC quedan sincronizados en segundos.
