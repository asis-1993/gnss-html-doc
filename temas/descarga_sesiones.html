Análisis de datos

Descarga de sesiones

El script descargar_datos.py descarga los archivos CSV desde Google Drive al equipo de análisis, organizados por día y sesión. La descarga es idempotente: si un archivo ya existe y su contenido no cambió, se omite.

Estructura de archivos en Drive

Los archivos se organizan en Google Drive bajo la carpeta del proyecto, agrupados por día de captura. Cada sesión genera tres archivos — uno por sensor:

proyecto-gnss/
├── 20260829/
│   ├── baro_20260829_002453.csv
│   ├── gnss_20260829_002453.csv
│   └── imu_20260829_002453.csv
├── 20260910/
│   ├── baro_20260910_190817.csv
│   ├── gnss_20260910_190817.csv
│   └── imu_20260910_190817.csv
└── ...

El nombre de cada archivo sigue el patrón {sensor}_{YYYYMMDD}_{HHMMSS}.csv, donde la hora corresponde al momento de inicio de la sesión de captura.

convención

El timestamp en el nombre es la hora local del sistema en el momento en que inició la adquisición. Dado que el RTC está sincronizado con NTP antes de cada sincronización, este timestamp es confiable como identificador de sesión.

Modos de operación

El script tiene tres modos, seleccionables mediante argumentos en la línea de comandos:

Listado — --listar

Muestra el inventario completo de sesiones disponibles en Drive sin descargar nada. Útil para planificar qué datos analizar antes de descargar.

python3 descargar_datos.py --listar

Salida típica:

INFO: Conectado a Google Drive.
INFO: Modo listado - no se descargará nada
INFO: 20260829: 11 sesión(es), 33 archivo(s)
INFO:    Sesión 20260829_002453: baro, gnss, imu
INFO:    Sesión 20260829_003701: baro, gnss, imu
...
INFO: 20260910: 3 sesión(es), 9 archivo(s)
INFO:    Sesión 20260910_190817: baro, gnss, imu

Un día — --fecha YYYYMMDD

Descarga únicamente las sesiones de la fecha indicada. Conveniente cuando se quiere trabajar con datos recientes sin esperar la descarga completa.

python3 descargar_datos.py --fecha 20260910

Descarga completa (sin argumentos)

Descarga todos los días disponibles en Drive. Los archivos que ya existen localmente y cuyo contenido no cambió se omiten automáticamente (verificación MD5).

python3 descargar_datos.py

Al finalizar, el script muestra un resumen:

Resumen:
  Archivos en Drive : 106
  Descargados       : 102
  Ya existían       : 4
  Con error         : 0

Estructura local de destino

Los archivos se guardan en el subdirectorio datos/ del repositorio, replicando la misma organización por día que tiene Drive:

gnss-project-analysis/
├── datos/
│   ├── 20260829/
│   │   ├── baro_20260829_002453.csv
│   │   ├── gnss_20260829_002453.csv
│   │   └── imu_20260829_002453.csv
│   └── 20260910/
│       └── ...
├── descargar_datos.py
├── token.json          ← no se sube a git (.gitignore)
└── .gitignore
importante

El directorio datos/ y el archivo token.json están excluidos del repositorio git mediante .gitignore. El token nunca debe commitearse — contiene credenciales OAuth que dan acceso a Google Drive del proyecto.

Verificación de integridad

Antes de guardar cada archivo, el script calcula el MD5 del archivo descargado y lo compara con el MD5 que reporta la API de Google Drive. Si coinciden, el archivo se guarda. Si ya existe un archivo local con el mismo MD5, la descarga se omite.

Este mecanismo garantiza dos propiedades:

  • Integridad: los archivos descargados son idénticos a los que subió la Raspberry Pi.
  • Idempotencia: ejecutar el script varias veces no duplica ni sobreescribe archivos que ya están correctos.

Requisitos

El script requiere el entorno conda gnss-analysis con las siguientes dependencias instaladas:

conda activate gnss-analysis
pip install google-auth-oauthlib google-api-python-client

Además, el archivo token.json debe estar en el mismo directorio que el script. Este token se genera una sola vez siguiendo el procedimiento de la guía Sincronización con Google Drive — el mismo token que usa la Raspberry Pi también es válido para la descarga, ya que ambos usan el scope drive.

scope OAuth

El script usa el scope https://www.googleapis.com/auth/drive — el mismo que usa sincronizacion.py en la Raspberry Pi. Ambos scripts comparten el mismo token.json, por lo que no es necesario generar un token separado para la descarga.

Anomalías conocidas

Sesión con archivo duplicado

La sesión 20260928_113445 contiene dos archivos barométricos en Drive (baro, baro, gnss, imu). Esto puede ocurrir si el script de sincronización en la Raspberry Pi subió el archivo dos veces debido a un error de red o una interrupción durante la verificación MD5. El script de descarga maneja este caso: descarga el primero y omite el segundo (mismo nombre, mismo contenido).
